# Windows Steam build 40423: the update of 2026-10-22

Transport Fever 3 updated on Steam from build 40420 (Steam build ID
25754343) to 40423 (25962684) on 2026-10-22, a few hours after release
1.3.2. The 1.3.2 hook, built for 40420, refuses it: no compiled native
bundle matches the new executable, so multiplayer stays off
(fail-closed). This note is the evidence for the new bundle
`profiles/tf3_build40423_steam_windows/`, now selected in
`profiles/native-build.txt`. It is static: the real-game acceptance
(GAME_TESTING.md) is listed as open at the end.

| identity | 40420 | 40423 |
|---|---|---|
| Steam build ID | 25754343 | 25962684 |
| SHA-256 | `74861ac4…fa602e4` | `e6c67da04bcdaaa61cef88db8e521e8763278811b788a329d2ee9758a658177e` |
| executable size | 69,755,832 | 69,876,664 |
| PE timestamp | `0x6AC50427` | `0x6AD0E4E5` |

The executable's own build string (`transportfever3.64-bit` then the
build) reads `40423`.

## Inputs and reproduction

A complete private `tpfre archive` of the installed game (7,188 files from
2,573 sources), outside Git, next to the 40420 archive. From the repository
root:

```powershell
$b = "$env:USERPROFILE/TPF3-MP-builds"
& ./tools/tpfre/target/release/tpfre.exe archive --game 'D:/SteamLibrary/steamapps/common/Transport Fever 3' --build 25962684 --steam-manifest 'D:/SteamLibrary/steamapps/appmanifest_3493540.acf' --out "$b/25962684-sources"
& ./tools/tpfre/target/release/tpfre.exe update --repo . --old "$b/25754343-sources" --new "$b/25962684-sources" --out "$b/runs/<new run>" --cache "$b/indexes" --jobs 2 --check-only
& ./tools/tpfre/target/release/tpfre.exe verify-build --repo . --archive "$b/25962684-sources" --json
```

Before the new bundle the run stopped at `signatures` and `native-bundle`
with the complete diagnosis: 122 changed, 7 added and 9 removed archived
files, 10 changed signatures, 42 changed or unknown containing-function
results, 118 changed scripts. With the bundle selected, `tpfre verify`
matches all 165 targets of the 40423 profile and `verify-build` exits 0
(`review_required: false`, `runtime_verified: false`).

## What changed in the game's code: the UI context grew

Almost every native change comes from one layout change: the UI objects the
main menu and the game's GUI keep (`CMenuUI`, `CGameUI`, and the context
object the tools' `Step` functions take) grew by **0x228 bytes**, at an
offset below `0x4b0`; a few fields of a second object moved by 0x38. Every
function the audit called changed was compared instruction by instruction
with addresses masked: the differences are these field displacements and
nothing else, except where named below. The tools' own fields, the
simulation, the network and the command layout did not change.

## Native data: what changed

Every constant of every bundle file was re-derived on 40423 from the code
that proves it on 40420 (old value reproduced first; instruction streams
compared with addresses masked; bytes read from the executable). Changed:

- `network.rs`: `EDGE_VTABLE` `0x3758c60` → `0x3770150`,
  `NODE_CONFIG_VTABLE` `0x3758ca0` → `0x3770190` (`UserdataValue<BaseEdge>`
  / `<BaseNodeConfig>`, constructors now `0x17818e0` / `0x175e690`, both
  instruction-identical). Sizes, payload and lane layout unchanged.
- `netread.rs`: the five `CompVec<T>` pool vtables, each `+0x17000`
  (BaseEdge `0x369fb08`, BaseNode `0x369fb78`, BaseNodeConfig `0x369fbe8`,
  Construction `0x36a0550`, RailroadCrossing `0x36a0128`), slot 0 their
  own `vf0`. Every size, stride and offset unchanged.
- `simperf.rs`: the wrapped vtable slots, `EmissionGridSystem` `0x371d1b0`
  (vtable `0x371d158` slot 11), `EmissionEmitterSystem` `0x371cb30`
  (`0x371cad0` slot 12), `TownSystem` `0x3729258` (`0x37291f8` slot 12);
  each slot holds the resolved profile target.
- `emission.rs`: the seven FNV-1a hashes. `Update` (now `0xaaf890`), the
  three dispatchers and the three kernels are instruction-identical to
  40420; only call and data displacements moved. Offsets unchanged.
- `edgewatch.rs` `PATHS` (log labels only): `0x11ebe6` queue, `0x12050f`
  script, `0x120384` direct, each a call of `CommandApply::One`
  (`0x9e84b0`). The 40420 bundle still carried 40408's values here.
- `industry_probe.toml`: identity only; its six signatures are unchanged.
- `native.rs`: Steam build ID and game build.

Unchanged, with the code that proves it compared: the command layout
(`PAYLOAD_INDEX 0x9b8`, `PLAYER_INITIATED 0x3d2`; the dispatcher's 64-entry
table, now at `0x9df29c`, keeps its case order, and entry 53 still calls the
WorldBuildProposal apply, now `0x9e7a00`, so `WORLD_BUILD_PROPOSAL` stays
52); modules, junctions, crossings, order and persons layouts; all 19 GUI
player sites' splice bytes, registers and kinds (`guiplayer.rs`); the tool
players' fields, the six tools' player stores, the bulldozer's filter and
owner list, the stop tool's busy byte (`+0x2c8`) and the street builder's
(`+0x9e0`); the tool chain's call distances; preview cancel; the builder
renderer (size `0x1d0`, upload `+0xf0`, state `+0x1b8`, list `+0x1af8`);
ticks, seeds, terrain, town field and traces; `GameState+0x20c` and the
GUI slot `+0x1e0`; and the step cadence fields: `CGame::Step` (`0x11f400`),
`CGame::Sync` (`0x11f6a0`) and `RunGameSimLoop` (`0x11e260`) are 40420's
instructions with only addresses moved, so `interval.rs`' layout holds and
40423 is added to its verified builds.

Shape changes seen, no constant affected: `CMenuUI::StartGame` gained a
`xor r8d,r8d` before a call (a callee took a third, zero argument);
`CMenuUI::DoStep` gained one 29-instruction block (`0x6a1b6c`), away from
both anchors; `SimEntityAtTerminalSystem::vf11` differs only in five assert
line numbers. The CMenuUI vtable (`0x36e81b0`) still has 60 slots with
`DoStep` at 52.

Weak points, as before: terrain's `SUB_MODELS 0x140`, `MODEL_SIZE 0xa8`
and `MODEL_TRANSF 0x60` were measured live on 40420; on 40423 only the code
that touches them is shown unchanged. `playerInitiated` at `+0x3d2` rests on
the unchanged apply, the payload copy and the identical Lua registration.

## Big Maps' plugin

`crates/tpf3mp-bigmap-plugin` is pinned to one executable (its package's
`builds`), so the 40420 package is refused on 40423, as it must be. Ported:
`src/build40423.rs` replaces `build40420.rs`. All 13 signatures match once
on the same, instruction-identical functions; registers, octree and
emission fields, the obstacle body, the spacing squares and the descent and
decoder checks are unchanged. Changed: the build's SHA-256, the two
vtable `lea`s' expected bytes (`grid_slot` `48 8D 05 48 EC C6 02`,
`emitter_slot` `48 8D 05 7B 26 C7 02`) and seven bytes of
`CREATE_GRID_BODY` (three call displacements, same callees, and the
factor load's displacement); the 0.0625f-to-0.125f distance is still
`0xf540`. `tests/game_40423.rs` runs the package against the 40423
executable and the 40423 profile. Its game mod's copied page
(`new_game_or_map_settings_page.tl`) and `difficulty_util.tl` are
byte-identical in both builds. A 40423 package must be published for
players who use Big Maps.

## Scripts and files

118 changed script paths, 5 added, 9 removed; the executable, `OpenAL32.dll`,
`SDL2.dll` and `alut.dll` changed; NVIDIA DLSS runtimes
(`nvngx_dlss.dll`, `nvngx_dlssnr.dll`) were added to the game folder.

- Simulation scripts that changed: `industries.script.tl` (a pause of
  industry closures during the tutorial, new persisted `version` and
  `pauseIndustryClosure`, a legacy upgrade of old saves),
  `mission_sim.script.tl` (the tutorial's end now unpauses subsidies and
  industry closures and makes locked entities bulldozable again; the GUI's
  Quit Tutorial button no longer unpauses subsidies) and
  `town_util.getProposalStats` (a replaced town building no longer counts as
  removed district capacity). All use existing commands; no new random use,
  no new command, no new component field. Every game of a room runs the
  same new code.
- Nothing the mod calls, wraps or replaces changed in a way that needs a
  change: `getActionParams` gained a ninth argument, which the stop tool
  capture forwards (`function(definition, ...)`); `cmd.d.tl` is
  byte-identical (61 command constructors, the guard's list); the subsidy,
  company, progression, town and loan scripts, `base/init.lua` and
  `industryutil.lua` are unchanged; the Teal API changes are additive.
- The mod's tutorial quit (`tpf3mp_sim.script.lua`) now gets the game's
  full cleanup in the simulation, subsidies included.
- Built-in ModWerkstatt mods: metadata tags, renamed construction parameter
  keys (`mw_lfsignale`, `mw_pr_signale`), new incompatibilities with Signal
  Distance, and a new placeable construction in `mw_cargo_load` under
  `content/asset/` (singular). The last one is a mod scan question that
  predates this update (`mw_maeuseturm` uses the same folder): left for
  its own change.
