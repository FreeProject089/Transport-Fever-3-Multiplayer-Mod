# Five gated channels: ordinary-start two-game acceptance, 2026-10-22

`acceptance.lua` kept four channels refused in rooms, and the hook kept the
street and track tools' continuation behind a test-only opt-in, each
pending an ordinary two-game run. This note records that run. It turns on
`perks`, `preservation`, `bulldozeStops` and `keptStops`, and makes
`TPF3MP_TOOL_CONTINUE` on by default. `crossings` (the crossing window,
whose real clicks take the rebuild shape the owner refused, 701fda20) and
`rejoinConstruction` (a non-atomic re-lay, BUILDING.md) stay off: a run
does not answer either.

## The runs

Ordinary start, as the crossing types' acceptance on 2026-10-19: one PC,
a local server and two launchers (Max, Max2) with their own identities,
links and game data; the room created in Max's launcher, joined by invite
in Max2's, the game started from the launcher. Windows Steam build 40423

## Found and fixed: the campaign with infinite money

In `gates-40423-a1` every game refused the campaign: `cannot read the
company balance for the campaign`. With the game's infinite money
`api.engine.util.finance.getPlayersBalance` answers nil
(`game_mechanics/finance/account.tl`: "nil --> infinite money"; the loan
script freezes for the same reason). The game's own tool then checks
nothing and still books the price (`marketing_campaign_tool.script.tl`:
`if availableMoney ~= nil and availableMoney < cost`). The apply now does
the same; a failed read, NaN or infinity is still refused. Every game sees
the same setting, so they agree. `gates-40423-a2` started the campaign in
both games.
